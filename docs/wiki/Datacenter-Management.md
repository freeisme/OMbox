# 机房管理

「机房管理」是导航里的一组页面，围绕机房里的**网络设备与服务器**展开：

| 页面 | 路径 | 作用 |
| --- | --- | --- |
| 网络设备/服务器 | `/datacenter-devices` | 机房设备台账：新增、修改、状态维护、Excel 导入 |
| 机柜视图 | `/rack-layout` | 把台账设备放到机柜 U 位，拖动改位置，上架/下架 |
| 设备面板 | `/device-panel` | 按型号渲染设备面板，维护端口与链路 |
| 网络拓扑 | `/topology` | 由端口连接自动分层生成拓扑图，可导出 SVG/PNG |
| 机房巡检 | `/inspection` | 按机房、弱电间或机柜发起巡检并输出巡检表 |

## 为什么机房设备要独立台账

机房里的交换机、防火墙、UPS、服务器**不是**办公终端，也不是按数量管理的 IT 物资。
把它们混进办公终端台账会导致未上架设备列表里出现大量笔记本，并把「领用/归还」这类人员流程
套到机柜设备上。因此：

* 机房设备单独存 `datacenter_device`；
* **机柜视图的「未上架设备」只来自这张台账**，办公终端与 IT 物资都不会出现；
* 办公终端与 IT 物资仍在各自模块管理，两边互不影响。

## 数据流

```text
型号库（厂商/型号/端口模板/面板图）
        │  按型号生成端口
        ▼
机房设备台账 ──上架──▶ 机柜位置(rack_device_placement) ──▶ 设备面板(端口) ──▶ 链路(cable) ──▶ 网络拓扑
        ▲                                   │
        └────────────── 下架（回到未上架） ──┘
```

* **上架/下架是唯一改变设备状态的地方**：上架写 `installed` 并记录所在机房与机柜，
  下架清空位置并回到 `stock`；
* **巡检**按机房、弱电间或机柜发起，与台账、机柜位置共享同一批机房对象；
* 机柜视图可以直接「发起巡检」，把当前机柜带到巡检模块。
