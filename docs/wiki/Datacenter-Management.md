# 机房管理

「机房管理」是导航里的一组页面，围绕机房里的**网络设备与服务器**展开：

| 页面 | 路径 | 作用 |
| --- | --- | --- |
| 网络设备/服务器 | `/datacenter-devices` | 机房设备台账：新增、修改、状态维护、Excel 导入、勾选导出设备信息 |
| 机柜视图 | `/rack-layout` | 把台账设备放到机柜 U 位，拖动改位置，上架/下架 |
| 设备面板 | `/device-panel` | 按型号渲染设备面板，维护端口与链路 |
| 网络拓扑 | `/topology` | 由端口连接自动分层生成拓扑图，可导出 SVG/PNG |
| 机房巡检 | `/inspection` | 按机房、弱电间或机柜发起巡检并输出巡检表 |

## 为什么机房设备要独立台账

机房里的交换机、防火墙、UPS、服务器**不是**办公终端，也不是按数量管理的 IT 物资。
把它们混进办公终端台账会导致未上架设备列表里出现大量笔记本，并把「领用/归还」这类人员流程
套到机柜设备上。因此：

* 机房设备单独存 `datacenter_device`；
* **机柜视图的「未上架设备」只来自这张台账**，办公终端与 IT 物资都不会出现；
* 办公终端与 IT 物资仍在各自模块管理，两边互不影响。

## 数据流

```text
型号库（厂商/型号/端口模板/面板图）
        │  按型号生成端口
        ▼
机房设备台账 ──上架──▶ 机柜位置(rack_device_placement) ──▶ 设备面板(端口) ──▶ 链路(cable) ──▶ 网络拓扑
        ▲                                   │
        └────────────── 下架（回到未上架） ──┘
```

* **上架/下架是唯一改变设备状态的地方**：上架写 `installed` 并记录所在机房与机柜，
  下架清空位置并回到 `stock`；
* **巡检**按机房、弱电间或机柜发起，与台账、机柜位置共享同一批机房对象；
* 机柜视图可以直接「发起巡检」，把当前机柜带到巡检模块。
* 台账表格可**勾选设备后导出设备信息**（CSV，含编号、名称、型号、类型、U 高、SN、固资编码、
  使用人、状态、所在机房与机柜、用途、远程访问地址、CPU/内存/硬盘、备注）；不勾选时导出当前
  筛选条件下的整张表。

## 文件库（配置文件归档）

机房页面第五个页签，按「机房/弱电间 → 设备」两级目录归档配置文件。

- **目录自动生成**：机房与设备建档后自动出现文件夹，无需手工建目录；
- **版本保留**：同名文件重复上传会生成新版本，列表里只有最新版标「当前」，旧版本保留可下载；
- **上传**：支持任意类型，单文件上限 50MB（`FILE_LIBRARY_MAX_BYTES` 可调）；
- **存储**：文件实体在 Docker 卷 `file-library-data`（容器内 `/app/file-library`），数据库只存元数据；
  备份时需要连同该卷一起备份；
- **记录**：上传 / 下载 / 重命名 / 删除都会写一条操作记录，可在「操作记录」里查看；
- **入口**：机柜视图右侧「设备属性」栏、网络设备/服务器列表操作列都有「配置文件」按钮，点击直达该设备文件夹。
