# 机房巡检

页面：`/inspection`。巡检对象**只包含机房、弱电间和它们下面的机柜**，
不包含办公区终端与 IT 物资仓库。

## 流程

1. **开始巡检**：选择模板与对象（一个机房/弱电间，或单个机柜），执行人默认是当前账号；
2. 开始后按模板**快照**出本次的全部巡检事项；
3. **逐项记录**：正常 / 异常 / 不适用，可填实测值与说明；
4. **异常必须填说明**，填写与提交两个环节都会校验；
5. 全部事项检查完才能**提交**，提交后任务与明细只读，不能修改也不能作废；
6. 输出**巡检表**：整页预览、导出 Excel（巡检表摘要 + 巡检明细）、打印视图
   （带巡检人 / 复核人签字栏）。

作废未提交的任务必须填写原因，并写入审计。

### 为什么填了还提示未检查

系统判定“已检查”的唯一依据是**该行选了结论**（正常 / 异常 / 不适用）。
只在输入框里写实测值或说明不算已检查——这也是它最容易踩的坑，尤其模板里的
「本次巡检发现的问题与处理建议」是文本型事项，很多人直接在框里写字但没点结论。

为避免这种情况，执行页现在：

* 数值 / 文本 / 选项型事项多一个「保存」按钮，点它按当前结论（没选就按正常）保存该行，
  在输入框里按回车也等价；
* 保存单项只刷新这一行和顶部统计，不会把其它行还没保存的输入冲掉；
* 输入内容实时暂存，切换页面或重新加载任务后会带回来；
* 点「提交巡检表」时，如果有"填了内容但没选结论"的行，会按事项名称提示你；
* 顶部统计直接显示「未检查」条数，提交报错也会列出具体是哪几项。

## 巡检模板

模板包含若干巡检事项，每项记：类别、事项、检查方法、取值类型（正常异常 / 数值 / 文本 / 选项）、
单位、正常范围、是否必填。

系统自带两张标准模板：机房巡检（16 项）与弱电间巡检（14 项）。
修改模板只影响**之后开始**的巡检，历史巡检表保留当时的快照。

## 扫码开检（可选）

打开形如 `/#inspection?rack=<机柜编码>` 的链接会自动进入巡检页并预选该机柜，
配合机柜上的二维码即可扫码开检；编码不存在时不弹窗。

## 权限与审计

权限模块 `inspection_management`（查看 / 创建 / 修改 / 删除 / 导出）。
审计动作覆盖：机房与机柜维护、模板维护、开始巡检、提交巡检、作废巡检。
