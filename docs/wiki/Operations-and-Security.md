# 运维与安全

## 权限模型

* 权限按「模块 + 操作」授权，例如 `it_assets:view`、`rack_layout:create`、
  `inspection_management:export`；
* 账号通过角色获得权限，也可以单独覆盖；角色带领域范围（超级管理员 / 管理员 / 普通 / 自定义）；
* 数据范围按组织过滤：后端在查询与写入时都校验，越权返回 `403`；
* **前端隐藏按钮不构成安全边界**，所有写接口都会重新校验权限与 CSRF。

## 审计

所有写操作写入 `audit_log`（动作、对象、变更前后、操作人、来源）。
机房管理相关动作包括：机房/机柜维护、型号维护与面板图上传、机柜上架与下架、
端口与链路的增删改、拓扑坐标保存、机房设备的新增/修改/删除/批量导入、巡检的开始/提交/作废。

## 备份

* 支持手动备份与按计划备份，备份文件记录文件名、大小、校验值与状态；
* 下载备份需要再次输入当前账号口令；
* 升级或迁移前必须备份，并验证备份可还原。

## 密钥与令牌

* 版本更新服务使用控件令牌通信，令牌只保存在服务器端配置中，不进入仓库与前端；
* 访问代码仓库使用 SSH 密钥或凭据管理器，私钥放在用户目录的 `.ssh/` 下，
  **绝不放进仓库目录**；
* 轮换密钥的顺序：先加新密钥 → 验证只读访问（`ssh -T git@...`）→ 再用于推送 →
  最后到平台吊销旧密钥。

## 脱敏纪律

仓库与 Wiki 均为公开内容，必须遵守：

* 不写真实内网地址、主机名、端口与拓扑；
* 不写本机绝对路径、账号口令、令牌、Webhook 密钥、证书与私钥；
* 不写真实员工姓名、工号、设备编号与固资编码，示例一律使用占位符；
* 推送前运行 `python tools/scan_release_safety.py --rev HEAD`。

## 部署注意

* 生产使用独立数据库账号，不建议用 root 运行应用；
* 反向代理终结 TLS，应用只监听内网回环；
* 容器与数据库统一时区（本项目的业务时间列均为北京时间）；
* 更新失败会自动回滚到上一个已知可用版本。
