# OMbox · 运维（O&M）盒子

面向内部 IT 部门的办公资产与 IT 服务管理系统：组织与人员、办公终端台账、IT 物资与多仓库、
离职回收、报废归档、工单与服务管理，以及机房管理（网络设备/服务器台账、机柜视图、设备面板、
网络拓扑、机房巡检）。

## 技术形态

| 项目 | 现状 |
| --- | --- |
| 后端 | Python 标准库（`http.server`），单进程同时提供 `/api/*` 与前端静态资源 |
| 前端 | Vue 3 + TypeScript + Vite + Element Plus，源码在 `frontend/`，产物输出到 `web/app/` |
| 前端引入方式 | Element Plus 按需引入 + 路由懒加载，首屏 JS 约 268 KB；旧前端（`web/app.js` 等）已整体删除 |
| 数据库 | MySQL 8.0+，迁移文件在 `database/migrations/` |
| 依赖 | 后端不引入第三方依赖；xlsx 解析、YAML 处理等均用标准库实现 |

## 版本与发布

- 版本号唯一来源是仓库根目录的 `VERSION`，后端通过 `GET /api/meta` 暴露；
- 每个可部署版本在 `VERSION_NOTES.md` 里有同名段落，并打 SemVer 注释标签；
- 发布前必须通过 `tools/scan_release_safety.py` 的脱敏扫描；
- 除非明确要求，更新只推送代码仓库，不自动部署、不同步内网镜像。

详见 [发布与版本](Releases-and-Versioning)。

## 人员与组织

- 「使用人员 → 新增人员」必须选择**所属组织**（组织树选择器，可按名称或编码筛选）；
- **工号可以留空**：留空时按所属组织自动分配 `<组织编码>-序号`（例如 `IT-01`），
  公用人员用 `SHARED-<组织编码>-序号`；自动分配的工号会写在保存成功的提示里；
- 编辑人员时清空工号不会改动原编号（公用人员除外），避免历史记录对不上；
- 工号在系统内唯一，手工填写与自动分配共用同一套唯一约束。

### 公用人员（v3.0.16）

「使用人员」里可以把人员状态设成**公用**（与在职 / 停用 / 离职并列），用来给**非个人使用**的
设备一个可挂靠的虚拟使用人（例如「某办公室公用」「某仓库公用」）：

* 一个组织下可以建多个公用人员，名称自己填，工号自动生成（`SHARED-<组织编码>-01`），也允许手工指定；
* 人员列表默认显示并带「公用」标签，可以按状态筛选；组织树的人数可以按需排除公用人员；
* 公用人员能被正常分配办公终端、显示屏与非资产物资，也能作为「离职资产转交」的接收人；
  对公用人员点「离职」相当于把它删掉（不进离职人员档案）；
* **禁止给公用人员绑定登录账号。**

### 领用设备 / 物资（v3.0.19）

「使用人员 → 设备」里的领用，点「＋ 领用」会先弹**领用确认**：

* 型号下拉会列出该类型的全部型号（库存为 0 的也会显示并标注「库存 0」）；
* **有库存**时显示「当前库存 X / 本次领用 N / 扣减后剩余 X−N」，
  可选择「扣除库存后分配」「不扣库存，直接分配」或取消；
* **无对应库存**（该仓库没这个型号 / 型号不在目录 / 没选出库仓库）时提示
  「无对应库存，是否直接分配？」；
* **库存不足**（要领的数量大于当前库存）时只允许「直接分配（不扣库存）」或取消，不会自动改数量；
* 选择「不扣库存」时只在人员名下登记这台设备，**不动库存、不产生库存领用记录**，
  以后回收时按"没有出库记录"的规则选仓库入库；
* 显示屏按单台登记（数量固定 1），同一个人可以领多台同型号显示屏，每台独立回收。

### 名下物资的三个动作（v3.0.24）

「使用人员 → 设备清单」里，每一条显示屏 / 非资产物资（含自定义物资）右侧都是**「操作」下拉**，
三个动作都会写一条**物资流转记录**：

| 动作 | 要填什么 | 结果 |
| --- | --- | --- |
| 回收 | 选择入库仓库（+ 可选备注） | 物资回到所选仓库库存，目录里没有的品牌型号会自动建档；流转记录方向为入库 |
| 报废 | 报废备注（必填，+ 可选补充说明） | **不回收入库、不回补库存**，直接从人员名下核销，并在「报废记录」留档；流转记录方向为减少、去向「报废」 |
| 调拨 | 选择接收人（在职或公用人员，+ 可选备注） | 只更换使用人，不动库存；接手人之后可以正常回收或报废这台物资 |

三条动作都会写审计日志；「物资流转记录」页按业务类型区分「收回入库 / 物资报废 / 物资调拨」。

## 权限与数据范围

系统按「权限模块 + 操作」授权（如 `it_assets:view`、`rack_layout:create`），
并按组织数据范围过滤；后端逐项校验权限，前端隐藏按钮不构成安全边界。
详见 [运维与安全](Operations-and-Security)。
