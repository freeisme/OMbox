# 员工工号规则

## 生成规则

```
工号 = 组织路径编码（去掉最顶层） - 三位顺序号
```

例：组织链 `集团(DEMO) → 苏州(HQ) → 研发中心(YF) → 材料开发组(LAB)`，
去掉最顶层后是 `DEMO1-HQ2-DEV3-LAB4`，该组第 12 个人的工号就是 `DEMO1-HQ2-DEV3-LAB4-012`。

要点：

- **只对留空的工号自动分配**，手工填写或导入的工号保持原样（但必须符合格式，见下）；
- 顺序号取「该组织已有最大号 + 1」，**不复用空号**（删人后新号不会倒回去）；
- 生成结果与全表比对去重，冲突自动顺延；
- 部门调整**不会改写已有工号**——工号跟着人，不跟着部门。所以历史员工的前缀与当前组织不一致是正常现象。

## 合规格式

`^(大写字母或数字分段, 至少一段) - (恰好三位数字)$`，例如 `DEMO1-HQ2-DEV3-LAB4-001`、`DEMO1-FIN2-003`。

不符合（如 `LAB4-01`、`001`、`ABC-XYZ`）的工号，在保存人员时会被按当前组织规则重算，
且**脏号不占用号段**，不会把下一个正常号码顶走。

## 工号体检

「使用人员」页面右上角 → **工号体检**：

| 分类 | 处理 |
| --- | --- |
| 格式不合规（少位、缺分段） | 点「修正」按规则重排 |
| 工号重复 | 点「修正」保留其一、其余顺延 |
| 前缀与当前组织不一致 | **默认不动**（历史遗留），仅在弹窗里提示数量 |

修正动作会写入操作日志（`action_type = employee_no_renumbered`），可追溯。
