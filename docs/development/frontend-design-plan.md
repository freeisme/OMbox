# 前端页面整体设计计划（布局规范与美化方案）

本文是新版前端（Vue 3 + Element Plus）的布局与视觉规范，以及分阶段的落地计划。
目标不是"再做一套设计系统"，而是把已建成的 16 个页面收敛到同一套骨架、令牌与组件上，
让后续加页面和改版不再各写一套样式。

## 一、参考依据

### 1. 指定文章的要点

参考文章《3 个必知的前端布局技巧，轻松打造美观页面》给出的三条主线及在本项目的对应做法：

| 文章要点 | 本项目对应做法 |
| --- | --- |
| 内容逻辑性（导航、信息按阅读顺序排列） | 保留「左侧导航 + 顶栏 + 内容区」骨架；列表页固定为「页头 → 筛选 → 批量操作 → 表格 → 分页」 |
| 视觉层次感（用颜色、字号、间距拉开主次） | 建立字号/颜色/间距令牌，层级只允许用令牌取值 |
| 设备兼容性（适配桌面、平板、手机） | 24 栅格 + 四档断点，明确每档下筛选、表格、双栏、抽屉的行为 |
| Flexbox 用于一维布局（导航、列表、卡片） | 顶栏、卡片头、工具栏、标签行统一 flex 写法，禁止再用 float |
| CSS Grid 用于二维布局（多列、动态内容） | 工作台模块区、指标卡区用栅格（el-row/el-col，底层即 flex/grid） |
| 响应式：断点、百分比流式、相对单位、图片自适应 | 断点统一四档；宽度用 flex/百分比；字号用令牌；面板图统一 max-width:100% |

文章属于入门级内容（三件套原理与示例）。本文在其基础上补充后台管理系统必需的
「令牌 → 组件 → 页面模板」三层结构与验收指标，否则仅靠 Flex/Grid 无法保证 16 个页面一致。

### 2. 现状盘点（实测）

| 指标 | 现状 | 说明 |
| --- | --- | --- |
| Vue 视图 | 19 个（16 个导航页 + 登录 + 旧页承载 + 壳） | 约 10 600 行 |
| 内联 style 片段 | 367 处 | 工作台 62、使用人员 36、设置 36、IT物资 24、巡检 23、工单 22 |
| 共享组件 | 1 个（LegacyFrame） | 卡片头、筛选栏、工具栏、空态、分页样式每页各写一遍 |
| 硬编码色值 | 14 处 | 其余 159 处已用 var(--el-*)，方向正确但未收口 |
| 全局样式 | app.css 196 行 | 只有外壳样式，缺令牌层与页面模板层 |
| 构建产物 | JS 1.1 MB / CSS 375 KB | Element Plus 全量引入 + 单 chunk |
| 断点覆盖 | 仅栅格列数（xs/sm/md） | 表格横向滚动、筛选折叠、抽屉宽度等小屏行为未定义 |

由此确定要解决的六个问题：

1. **P0 无设计令牌**：间距、字号、圆角写在内联样式里，改一处要翻 19 个文件。
2. **P0 无共享组件**：同一张列表页的骨架被重复实现 10 次以上。
3. **P1 响应式只做了一半**：只有列数变化，缺小屏可用性规则。
4. **P1 视觉层次不统一**：有的页面卡片套卡片，有的用分隔线；标题字号各页不同。
5. **P1 可访问性缺口**：自定义可点击 div（待办项、队列项）不可键盘操作、无 role。
6. **P2 性能**：Element Plus 全量引入 + 单 chunk，首屏代价偏高。

## 二、设计原则

- **密度优先**：内部台账系统一次要扫几十行数据，行高与留白以"看得清又不浪费屏幕"为准。
- **一个页面一个主张**：页头说明这页能做什么，其余区域只做筛选、数据与操作。
- **令牌唯一**：任何颜色、间距、字号都来自令牌，不允许魔法数字。
- **可预测**：同类页面（列表、详情、表单）用同一套骨架，位置固定，用户不用重新找。
- **可键盘操作、可主题化、可降级**：无鼠标可用；主题色可换；接口失败时页面其余部分照常。

## 三、设计令牌（阶段 1 交付）

新增 frontend/src/styles/tokens.css，全部以 CSS 变量暴露，由 app.css 引用一次。

| 类别 | 令牌 | 取值 |
| --- | --- | --- |
| 间距 | --oa-space-1 … -6 | 4 / 8 / 12 / 16 / 24 / 32 px（4 的倍数） |
| 页面留白 | --oa-page-padding | 16px（<768px 时 12px） |
| 卡片间距 | --oa-gap | 12px |
| 字号 | --oa-font-xs/sm/md/lg/xl/2xl | 12 / 13 / 14 / 16 / 20 / 28 px |
| 行高 | --oa-line-tight/normal | 1.3 / 1.6 |
| 圆角 | --oa-radius-sm/md/lg | 4 / 6 / 8 px |
| 边框 | --oa-border | 1px solid var(--el-border-color-lighter) |
| 面层 | --oa-canvas / --oa-surface | 页面底色 / 卡片底色（随深浅色切换） |
| 表格密度 | --oa-row-compact/default | 32 / 40 px（列表默认紧凑） |
| 状态色 | 复用 --el-color-success/warning/danger/info | 不再自定义状态色 |
| 主题色 | 复用 --el-color-primary 及其 light/dark 派生 | 已由 theme.ts 运行时注入 |

硬性约定：视图里不再出现十六进制色值（现有 14 处清理掉），不再出现裸 px 间距。

## 四、布局规范

### 1. 页面骨架

业务页面统一为下面这条纵向顺序，缺项可省略、顺序不可变：

    页头 PageHeader（标题 + 一句话说明 + 右侧主/次操作）
    筛选区 FilterBar（栅格化，含"更多筛选"折叠）
    批量操作条 ToolbarActions（仅列表页，未选中时禁用）
    数据区 DataPanel（表格 / 树 / 卡片组）
    分页 Pagination（右下对齐）

详情类内容一律用右侧抽屉（Drawer），不新开页面；跨模块的完整编辑用弹窗（Dialog）。

### 2. 栅格与断点

24 栅格（Element Plus 默认），四档断点与行为：

| 断点 | 宽度 | 筛选区 | 表格 | 双栏页 | 抽屉 |
| --- | --- | --- | --- | --- | --- |
| XL | ≥1200px | 4–6 列 | 全列展示，操作列固定右侧 | 左 300px + 右自适应 | 640px |
| L | 992–1199px | 3–4 列 | 次要列可隐藏 | 左 260px + 右自适应 | 560px |
| M | 768–991px | 2 列 | 横向滚动 | 上下堆叠（树在上） | 100% |
| S | <768px | 1 列，次要筛选折叠 | 横向滚动，保留首列与状态 | 上下堆叠，树默认收起 | 100% |

实现方式：沿用 el-row/el-col 的 :xs/:sm/:md，但筛选区必须显式声明三档，
不允许只写 :md（当前多数页面正是如此）。

### 3. 表格规范

- 固定表头（height 或 max-height），行高使用紧凑密度；
- 列宽策略：标识列给 min-width 自适应，状态/时间/操作列给固定 width；
- 操作列 fixed="right"；危险操作只在操作列出现，并用 type="danger" 文本按钮；
- 数值列右对齐并使用等宽字体；长文本列统一 show-overflow-tooltip；
- 空数据统一用 empty-text，不写自定义空态 DOM。

### 4. 卡片与分区

- 一级容器一律 el-card shadow="never" + 1px 边框，不再嵌套卡片；
  需要分组时用 el-divider + 小标题（14px/600）；
- 卡片间距 --oa-gap（12px），页头卡片与数据卡片之间同样 12px；
- 指标卡（工作台）大屏并排 4 列、中屏 2 列、小屏 1 列。

### 5. 双栏页

使用人员、基础字典、机房巡检的「左树右表」固定为：左栏 300px（L 档 260px）、右侧 min-width:0
自适应并按需横向滚动；小屏改为上下堆叠且左侧默认收起。

## 五、组件规范（阶段 1–3 交付）

新增 frontend/src/components/ui/，逐步替换各页重复实现：

| 组件 | 职责 | 替换掉 |
| --- | --- | --- |
| PageHeader.vue | 标题 + 说明 + 右侧操作插槽 | 19 处页头内联结构 |
| FilterBar.vue | 栅格化筛选区 + 重置 + 结果计数 | 10 余处筛选表单 |
| ToolbarActions.vue | 批量选择、导出、新增等操作条 | 列表页工具条 |
| DataPanel.vue | 统一卡片容器（边框 + 头部/尾部插槽） | 大量内联样式的 el-card |
| StatusTag.vue | 状态 → 颜色/文案唯一映射（复用 labels.ts） | 各页重复的 el-tag 三元表达式 |
| EmptyHint.vue | 统一空态（文案 + 尺寸 + 可选操作） | 各处不同尺寸的 el-empty |
| MetricCard.vue | 指标卡（数值 + 说明 + 可选跳转） | 工作台 4 张卡的内联样式 |
| FormDialog.vue | 弹窗表单统一宽度、footer、提交禁用与 loading | 11 处弹窗 |
| DetailDrawer.vue | 详情抽屉统一宽度与分组标题 | 6 处抽屉 |
| useConfirm.ts | 危险操作二次确认（统一文案模板） | 各处 ElMessageBox.confirm |

约定：组件只接收数据与回调，不直接调用接口；颜色与间距一律来自令牌。

## 六、美化方案（视觉）

- **层次**：页面标题 20px/600，页头说明 13px 次要色，卡片头 14px/600，正文 14px，辅助 12px；
- **色彩**：主色仅用于主按钮、选中态、进度；状态色只用于标签/进度/图标；危险色只用于删除与报废；
- **图标**：把当前用于导航/按钮的字符图标（▣ ✎ ♙ ⌗ ☰ ⚑）统一替换为 Element Plus 图标组件，
  保证字号、对齐与可访问性一致；
- **表格**：表头底色 --el-fill-color-light，斑马纹 + hover 高亮，选中行使用主色浅底；
- **留白**：卡片内边距 16px、卡片头与内容 12px、表单控件间距 8px；
- **动效**：页面切换 150ms 淡入（沿用现有 page-enter）；列表刷新只做 loading 不做位移；
  全部动效遵守 prefers-reduced-motion；
- **深浅色**：新增样式只允许使用变量，html.dark 下不得出现写死的白底黑字。

## 七、可访问性

- 可点击元素必须是 button/el-button；确需行级点击的卡片改为 role="button" + tabindex="0"
  并支持回车与空格（工作台待办项、服务队列项当前不满足）；
- 正文对比度 ≥4.5:1，辅助文字 ≥3:1；
- 图标按钮必须有 title；表格首列给出可读的 aria-label；
- 表单 label 与控件正确关联；禁止自定义 outline: none；
- 三态规范：加载（v-loading）、空（EmptyHint）、错误（就地 el-alert + 重试）。

## 八、性能与工程

| 措施 | 预期效果 |
| --- | --- |
| Element Plus 按需引入（unplugin-vue-components + unplugin-auto-import） | JS 1.1 MB → 约 400–500 KB（gzip ≤180 KB） |
| 路由懒加载，工作台之外页面按需分包 | 首屏只需外壳与工作台 |
| 办公终端 / 使用人员 / IT物资 改服务端分页筛选接口 | /api/state 549 KB → 单页 ≤40 KB |
| 样式只走 scoped + 令牌 | 减少全局污染与重复 CSS |
| 新增校验脚本：禁止视图出现十六进制色值与裸 px 间距 | 规范可自动执行，不靠人盯 |

## 九、实施计划

每个阶段独立发布（版本号 + 版本说明 + 推送 GitHub）。每阶段结束都必须跑：
单元与结构回归 → vue-tsc 类型检查 → Vite 构建 → 浏览器端到端（含四档断点截图对比）→ 脱敏扫描 → CI 全绿。

| 阶段 | 内容 | 产出 | 验收标准 |
| --- | --- | --- | --- |
| 阶段 1 令牌与共享组件 | tokens.css + PageHeader / DataPanel / FilterBar / StatusTag / EmptyHint | 令牌与 5 个基础组件 | 工作台、操作日志、离职人员三页迁移完成；三页内联样式片段下降 ≥60%，视觉无回归 |
| 阶段 2 列表页统一 | 办公终端、使用人员、IT物资、物资流转、报废记录、工单迁移到统一骨架 | 10 张列表页同骨架 | 新组件复用率 ≥80%；内联样式总量 ≤150 |
| 阶段 3 表单与详情统一 | FormDialog / DetailDrawer / useConfirm 覆盖 11 处弹窗与 6 处抽屉 | 弹窗抽屉一致化 | 宽度、footer、校验、确认文案统一；无页面自定义弹窗样式 |
| 阶段 4 性能与响应式 | 按需引入 + 路由懒加载 + 服务端分页接口 + 断点验收 | 性能与适配达标 | 首屏 JS ≤500 KB；四档断点无横向溢出与遮挡 |

阶段 4 的服务端分页需要配套后端接口（GET /api/computers、/api/employees、/api/inventory），
可复用工作台 /api/workbench/summary 的权限与数据范围过滤方式，保证与列表口径一致。

## 十一、落地结果（截至 v2.31.0）

阶段 1–4 已全部完成，实际数据与目标的对照：

| 指标 | 起点 | 目标 | 实际 |
| --- | --- | --- | --- |
| 视图内联 style 片段 | 367 | ≤80 | **31**（另有 12 处动态 `:style`，用于机房画布定位） |
| 共享 UI 组件 | 1 | ≥10 | **10**（7 个骨架组件 + FormDialog / DetailDrawer / useConfirm） |
| 硬编码色值 | 14 | 0 | **0**（视图内） |
| 首屏 JS | 1.3 MB | ≤500 KB | **268 KB**（gzip 114 KB） |
| 响应式断点覆盖 | 2 档（列数） | 4 档 | **4 档**（XL/L/M/S，含导航折叠、抽屉全宽、表格横向滚动） |
| 列表行高 | 混合（32–48px） | 统一 32px | 主列表统一 32px（使用人员曾因操作列过窄被顶到 41px，v2.31.1 修正） |
| 每阶段 CI | 全绿 | 全绿 | 全绿 |

各阶段实际交付：

- **阶段 1**：`tokens.css` + `PageHeader` / `DataPanel` / `FilterBar` / `StatusTag` /
  `EmptyHint` / `MetricCard` / `ToolbarActions`；工作台、操作日志、离职人员三页迁移完成。
- **阶段 2**：19 个页面的列表骨架统一（办公终端、使用人员、IT物资、物资流转、报废记录、
  工单、基础字典、同步与质量、服务管理、机房巡检、设置等）。
- **阶段 3**：`FormDialog` / `DetailDrawer` / `useConfirm` 覆盖 22 处弹窗、6 处抽屉与
  8 处危险操作确认；弹窗宽度收敛为 sm/md/lg/xl 四档，footer 与 loading 统一。
- **阶段 4**：Element Plus 按需引入 + 路由懒加载；办公终端改服务端分页
  （`GET /api/list/computers`，264 行只传当前页 28 KB）；`GET /api/state?include=` 按需裁剪，
  办公终端页 549 KB → 91 KB、IT 物资页 → 44 KB；四档断点生效。

未做（明确记录的取舍）：

- 使用人员的**人员清单**、IT 物资的**目录树**未改成服务端分页——前者要按组织树统计人数、
  还要在离职转交里用全量人员，后者是目录树；两者改为请求裁剪后的快照，
  整包体积分别降到约 106 KB 与 44 KB（使用人员的终端已改为 `fields=names` 精简投影 +
  设备弹窗按需取数）。
- 小屏筛选区只做单列堆叠，没有做「更多筛选」折叠。
- 机房画布类页面（机柜视图、设备面板、网络拓扑、机房设备）保留动态定位的 `:style`，
  这类值由运行时坐标决定，不属于硬编码样式。

## 十二、明确不做（避免过度设计）

- 不引入第二套 UI 框架或自研组件库，继续用 Element Plus；
- 不重做深浅色主题（已具备），只保证新样式遵守变量约定；
- 不引入动画库、图表库或 CSS-in-JS；
- 不为个别页面开特例样式；确有差异时优先扩展组件 props；
- 不动业务逻辑与接口契约，本计划只涉及呈现层。
